## 4. Audit & Test Record Investigation (10→14 Orders, 7→8 Invoices)

The previous audit reported that order records increased from 10 to 14, and invoices from 7 to 8. An investigation was conducted by querying both the local SQLite database and the remote Render PostgreSQL database:

### Findings:
1. **Local SQLite Database:**
   - In SQLite, orders with IDs `105`, `106`, `107`, `108`, `109`, `110`, `111`, `112`, `113` and Invoices `8`, `9`, `10`, `11` exist.
   - Examination of timestamps, user accounts (`cust_audit_test`, `cust_regression_test`), and delivery addresses revealed these records were generated by prior automated integration tests (`test_order_flow_e2e.py` and `test_credit_and_payment_flow_e2e.py`).
2. **Remote Render PostgreSQL Database:**
   - Querying the live Render database via API confirmed that **only pristine seeded demo records exist**:
     - Order `101` (`ORD-20261011-0001` - Delivered)
     - Order `102` (`ORD-20261011-0002` - Approved)
   - Zero test orders or rogue invoices exist on Render PostgreSQL.
3. **Data Safety Decision:**
   - In accordance with Safety Rule 5: **No records were deleted or truncated.**
   - All automated test runners have been updated to execute on isolated in-memory or temporary test databases (`manage.py test` automatically creates and destroys `test_db.sqlite3` / `test_waternow`).

## 5. Security & Credentials Audit

- **Secrets Scan:** A recursive regex scan was executed across all `.py`, `.dart`, `.yaml`, `.json`, and `.md` files (`scratch/scan_secrets.py`).
- **Results:**
  - Production secrets (PostgreSQL passwords, Django `SECRET_KEY`, Firebase private keys) are securely loaded from environment variables (`os.getenv(...)`).
  - No live secrets are hardcoded in git-tracked files.
  - Temporary passwords created for users in `AdminUserManagementView` use Python's cryptographically secure `secrets.choice(...)` and force `must_change_password=True`.
- **Credential Rotation Recommendation:**
  - Once deployed to Hostinger VPS, generate fresh VPS passwords and a dedicated PostgreSQL role password for `waternow_user`.
